# 官网探索整改：实测结果与验收缺口（2026-10-16）

**整项验收尚未通过，未发布。** 已实现计划中的调度、复用、恢复和验证机制，也完成了五校受限真实 API 对照；但主要参考来源覆盖、完整部门归属及费用收益没有达到可证明整项合格的程度。下面将已修复、已测量和未通过分别记录，不以测试数量或通知总量宣布完工。

范围为官网结构探索、来源发现与接入；用户后来明确同意修复发布时间元数据识别。正文内容提取、附件读取和阅读界面保持原实现。没有添加独立渠道页面、通用多 Agent、云端来源库、本地模型或默认完整浏览器。

针对实际失败保留了以下前后对照，均非新一轮付费接入结果：

- 人大目录的重复组件识别消除了两个重复栏目识别任务；三个实际修复区域的列表材料分别由 24/19/30 批降为 1/2/2 批。字节数减少不冒充实际 token 节省。
- 浏览器关闭时的晚到限速许可原先可能残留，导致排队；修复后原先受影响的 7 条人大原文全部获得材料，每次结束后的浏览器许可占用为 0。该小样本不证明所有网络超时都已消失。
- 北师大部分错误 HTTPS/HTTP 跳转只在精确对应本次实际地址时兼容，6 个入口中 5 个成功，1 个仍连接失败。
- 天津大学“学院（部）”被当成单个单位，已按通用院系集合词法修复；原失败 API 对照保留，不改写成通过。
- 华科同一招生首页的两个真实地址曾接成两个来源。相同完整 HTML、真实“首页”自链接、相同发布者和实际栏目节点共同证明后，留存材料回放由 2 个变为 1 个来源；不合并历史重复行。
- 同一列表行包含不同文章链接时曾错误复用来源，已要求非修复复用的标题/链接规则一致，并保留实际物理栏目验证。
- 中科大四个学院共用官网栏目原先投到 13 个学院/下属系位置，修复后回到 4 个学院位置；明确的系专属栏目仍保留。历史单位→栏目旧边也不能继续扩大订阅范围，显式选中的来源不变。
- 华科真实正文在 `div.nav_right` 布局中，旧来源验证把整块删掉，只剩 1 个段落。现在须完整可见标题、局部已验证发布字段及实质段落共同证明，才保留外层布局；相同原始 HTML 回放保留 29 个段落和真实标题。真正的导航、侧栏、隐藏及未加载内容仍不能提供接入证据。仅改接入试抓验证，不改正文引擎。旧版已保存的相应失败也沿用原网页和付费决定重新执行程序验证，不更换轮次或重新购买规则；版本6旧失败的受控前后对照由unsupported变为connected。

## 来源参考与通知抽检

- 7 所不同结构高校共 70 个已确认参考来源：华科、中石克、交大、中科大、人大各 10，天津大学 9，北师大 11。其中 60 个保留当日实际页面；10 个中石克历史参考当前访问失败，明确保留历史日期，不冒称当日连通。**70 是参考清单，不能当作程序成功接入 70 个。**
- 样本覆盖普通 HTML、多层目录、动态材料、同页多栏、同名/共用网站、附件和空栏目；自动接入是否逐项覆盖这些类型，仍需以实际结果记录，不能只凭参考材料存在就判通过。
- 100 条标题及原文地址均不重复的实际通知，人大、华科、交大、天津大学、北师大各 20 条。独立查阅真实原文和列表成员；同一通知多处发布的关系不丢弃，也不重复计入 100 条。
- 日期旧实现 31 条正确；修复后 96 条正确，4 条维持未知：1 条只有两位年份、2 条仅有更新时间、1 条材料不足。最初审查辅助脚本把两位年份补世纪的假设已撤回，原始记录保留。此次前后比较复用完整真实 HTML，新增官网及模型请求均为 0，不冒充又做一轮联网。
- 另核对 101 个来自实际接入试验的原文地址，六校分布为 23/35/14/15/11/3，完整可见标题与列表标题一致。包含天津大学早期基线和两对同题多处发布，只有 99 个“学校+标题”组合，不能称 101 条独立通知。实际列表节点成员关系、栏目标题和原文分别留证；没有据此把全部部门归属标为正确。
- 结构调度 v14 冻结后独立学校为华科和中科大。天津大学失败推动了目录词法修正，因此退出独立集。华科后来又推动了日期、别名及布局修复，中科大推动了共用官网归属修复；**两校只能作为未用于调整该版结构调度参数的对照，不是最终所有模块的全新独立验收集。** 最终整体仍缺两所未参与调整学校的完整复验。

## 持续运行与费用账本

| 行为 | 证据 | 结论边界 |
| --- | --- | --- |
| 无新通知 | 人大博士/硕士招生两个现有来源，经正常更新接口各检查 12 条，新增 0；新增 AI 请求及 token 均为 0 | 实网验证两来源；不是长周期稳定性保证 |
| 中断恢复 | 人大同一数据库继续，原付费执行身份、输入摘要、usage、服务商请求号及学校预算键不变 | 实际继续有增量账本；不存在借重启重新支付未知请求 |
| 额度停止后程序处理 | 达 100 次共同上限后，保存材料继续接入 2 栏目，新增 AI 为 0 | 明确没有提高本机上限 |
| 新通知 | 受控保留材料下的正常采集、已知配置复用检查 | 尚无等待官网自然发布的新通知实网观察，不能标真实验收通过 |
| 网站改版 | 真实历史变化材料及受控规则变化检查，先验证新规则再替换，失败不破坏其他来源 | 尚无本轮自然改版的长期跟踪结果 |

调查全部历史（含早期失败和多次 A/B）为 **438 次已发送、2,089,497 已确认 token，另有一次历史未知结果的 13,972 token 预留，当前在途 0**。确认数加预留是 2,103,469，不能称这部分全部已实际消费。此总量不能当作本次某校的生产成本，也不能隐去早期浪费。

最终五校新对照是 30 次/101,217 token；此前天津大学失败对照 8 次/25,420 单独保留。历史未知人大请求在收到部分响应后超时，没有最终 usage，不能判定故障一定来自 VPN 或服务商，也没有重新支付重发。

零新增付费复用银行试验因新输入摘要不匹配，没有产生可比接通结果，不能冒充省费成功。早期两个独立空白环境的相同标识存在不同答案，准备复用银行时全部排除有歧义项并保留原件，禁止挑选有利答案。

**本轮保留现有生产默认引擎。** 当前没有观察到额外相关入口，实测不足以支持整体替换的成本。独立适配器继续供诊断，不加入默认依赖、不默认启用逐页 LLM 或下载完整浏览器。对照见[引擎测量](../tests/acceptance/crawl_engine_comparison_20261016.json)。
