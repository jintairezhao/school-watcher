# 官网探索整改：实测结果与验收缺口（2026-10-16）

**整项验收尚未通过，未发布。** 已实现计划中的调度、复用、恢复和验证机制，也完成了五校受限真实 API 对照；但主要参考来源覆盖、完整部门归属及费用收益没有达到可证明整项合格的程度。下面将已修复、已测量和未通过分别记录，不以测试数量或通知总量宣布完工。

范围为官网结构探索、来源发现与接入；用户后来明确同意修复发布时间元数据识别。正文内容提取、附件读取和阅读界面保持原实现。没有添加独立渠道页面、通用多 Agent、云端来源库、本地模型或默认完整浏览器。

针对实际失败保留了以下前后对照，均非新一轮付费接入结果：

- 人大目录的重复组件识别消除了两个重复栏目识别任务；三个实际修复区域的列表材料分别由 24/19/30 批降为 1/2/2 批。字节数减少不冒充实际 token 节省。
- 浏览器关闭时的晚到限速许可原先可能残留，导致排队；修复后原先受影响的 7 条人大原文全部获得材料，每次结束后的浏览器许可占用为 0。该小样本不证明所有网络超时都已消失。
- 北师大部分错误 HTTPS/HTTP 跳转只在精确对应本次实际地址时兼容，6 个入口中 5 个成功，1 个仍连接失败。
- 天津大学“学院（部）”被当成单个单位，已按通用院系集合词法修复；原失败 API 对照保留，不改写成通过。
- 华科同一招生首页的两个真实地址曾接成两个来源。相同完整 HTML、真实“首页”自链接、相同发布者和实际栏目节点共同证明后，留存材料回放由 2 个变为 1 个来源；不合并历史重复行。
- 同一列表行包含不同文章链接时曾错误复用来源，已要求非修复复用的标题/链接规则一致，并保留实际物理栏目验证。
- 中科大四个学院共用官网栏目原先投到 13 个学院/下属系位置，修复后回到 4 个学院位置；明确的系专属栏目仍保留。历史单位→栏目旧边也不能继续扩大订阅范围，显式选中的来源不变。
- 华科真实正文在 `div.nav_right` 布局中，旧来源验证把整块删掉，只剩 1 个段落。现在须完整可见标题、局部已验证发布字段及实质段落共同证明，才保留外层布局；相同原始 HTML 回放保留 29 个段落和真实标题。真正的导航、侧栏、隐藏及未加载内容仍不能提供接入证据。仅改接入试抓验证，不改正文引擎。旧版已保存的相应失败也沿用原网页和付费决定重新执行程序验证，不更换轮次或重新购买规则；版本6旧失败的受控前后对照由unsupported变为connected。

## 持续运行与费用账本

| 行为 | 证据 | 结论边界 |
| --- | --- | --- |
| 无新通知 | 人大博士/硕士招生两个现有来源，经正常更新接口各检查 12 条，新增 0；新增 AI 请求及 token 均为 0 | 实网验证两来源；不是长周期稳定性保证 |
| 中断恢复 | 人大同一数据库继续，原付费执行身份、输入摘要、usage、服务商请求号及学校预算键不变 | 实际继续有增量账本；不存在借重启重新支付未知请求 |
| 额度停止后程序处理 | 当时达 100 次共同上限后，保存材料继续接入 2 栏目，新增 AI 为 0 | 该次沿用当时上限；用户后来改为 300，历史试验不改写 |
| 新通知 | 受控保留材料下的正常采集、已知配置复用检查 | 尚无等待官网自然发布的新通知实网观察，不能标真实验收通过 |
| 网站改版 | 真实历史变化材料及受控规则变化检查，先验证新规则再替换，失败不破坏其他来源 | 尚无本轮自然改版的长期跟踪结果 |

调查全部历史（含早期失败、多次 A/B 及后述恢复诊断）为 **447 次已发送、2,133,318 已确认 token，另有一次历史未知结果的 13,972 token 预留，当前在途 0**。确认数加预留是 2,147,290，不能称这部分全部已实际消费。此总量不能当作本次某校的生产成本，也不能隐去早期浪费。

最终五校新对照是 30 次/101,217 token；此前天津大学失败对照 8 次/25,420 单独保留。历史未知人大请求在收到部分响应后超时，没有最终 usage，不能判定故障一定来自 VPN 或服务商，也没有重新支付重发。

零新增付费复用银行试验因新输入摘要不匹配，没有产生可比接通结果，不能冒充省费成功。早期两个独立空白环境的相同标识存在不同答案，准备复用银行时全部排除有歧义项并保留原件，禁止挑选有利答案。

## 低接入、缓存及调用结果的后续核查

用户把每校请求上限改为300后已只读核实并沿用；旧100次上限试验没有改写成300次。该100次是多个隔离试验的累计，不是最新机制100次才接入2个。

- 人大真实院系目录可完整读取，不能把遗漏统一解释为异步渲染。三处实际HTTP入口连接断开、另两处返回有代理路由失败证据的502；五处浏览器均能打开。来源探索现在按已观察的失败及时尝试一次浏览器，保留原地址、失败证据、限速和Retry-After；不修改正文读取，也不把网络故障当成规则错误。
- 同一隔离数据库的受限恢复新增6次实际请求、34,408确认token，原有2个栏目/24条内容未增加，因此这轮**未通过接入收益验收**。六次模型输出都通过格式校验，说明调用成功率不能代替实际接入效果；其中五次花在校园导览页。
- 校园页三块发布区域与已观察官网导航的完整DOM签名完全相同。原复用只覆盖目录角色，遗漏了校园/部门/栏目等页面。已按实际DOM统一检查，并在旧待办继续付费前重查。原网页及原付费计划回放复用3块、增加0次官网读取/模型调用，原计划字段和费用行保持不变。主内容有独立发布列表时仍保留；不合并来源ID。
- 截图的服务商输入缓存命中率为421,120 ÷ (421,120＋447,559)＝48.5%。服务商按已持久化的共同前缀匹配，不能把它等同本地材料/成功配置复用，也不能承诺固定命中率。该六次新诊断实际输入33,262token，其中命中7,296，即21.9%；小样本不代表生产总体，首先应消除重复请求。
- 本机近30天调用统计包含旧分类机制的大量归属校验失败。按北京时间读取当日记录的快照中，99次已结束调用均通过输出校验；这不证明99次都接入成功。历史缓存明细未保存，不能追补为0命中。已保留服务商实际返回的命中/未命中输入计数，并按有明细的输入统计，原确认token不扣减。
- 随后的零新增AI恢复在191.02秒主动停止排查，仍未增加接入。真实工作队列记录了92次普通读取结果，同一试抓地址最多重复32次；浏览器已有6次导航结果，却只返回3次结果回放。根因之一是官网探索转交浏览器后重新选择了其他待办，没有继续原网页。现已保存当前读取位置，交接后按原位置恢复，旧浏览器进度按完整请求摘要匹配；受控任务桥接只发送一次HTTP、一次浏览器请求，之后轮询原结果，61项相关检查通过。来源接入的样本验证也单独使用已证明可用的读取切换，日常正文任务不继承这项变更。
- 修复后同一人大数据库、原学校轮次继续420.039秒，新增AI请求和token均为0，接入栏目由2增至5，保存内容由24增至89。浏览器26次实际结果均被原任务取回；此前重复32次的试抓原文在本段只读1次，单地址最多2次。旧付费决定、已有来源ID及未知费用请求保持原样。这是留存进度的增量恢复，时窗和前段不同，不能冒称冷启动对照或吞吐提升倍数。新增内容含旧新闻、科研和招生资料，新增三栏目仍待独立核对归属与主要需求覆盖。
- 在真实留存前沿发现，深层专题继承七项需求后仍会抢在未观察院系前面。已增加有限的主干首轮观察：只有真实官网目录及当前页面哈希、实际链接和节点位置共同支持的单位入口，或官网直接相关入口，才先于深层分支；按自身标签排序，已读过的入口不重复享有首轮优先，最旧待办轮转保留。相同前沿回放中，三个正常轮次原选“专题研讨会”，修复后未观察的党委学生工作部入口优先；这仅证明调度变化，实际联网覆盖正在另行验证，不能算新增来源。
