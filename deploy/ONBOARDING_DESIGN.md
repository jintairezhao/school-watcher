# 学校自动接入重构方案

## 目标与边界

订阅学校后，沿官网公开导航建立准确、可选择的部门与栏目树：保留院系、职能部门、下属单位和官网分组，栏目挂到正确部门，选择部门后自动包含其后续新增栏目。首批通知可用只是基础验收，不等于部门结构验收完成。AI 是解析器的补充，不能成为启动前提。单个栏目失败不阻塞其他栏目；没有完整访问官网时，不声称全校覆盖。

保留统一网页获取、公开地址限制、持久队列、通知去重、订阅、已读、收藏与现有有效规则。自动接入不再依赖候选提案、独立重复读取、部门归属复核和激活审批。旧审核记录与手动配置接口保留兼容，不能删除用户数据。

## 执行架构

1. `discover` 只负责遍历官网主页、机构目录、部门主页和发布栏目；保存已访问页面和真实导航关系。每批发布发现结果并派发独立 `onboard` 任务。
2. `onboard` 以学校及栏目页面 URL 为稳定身份，优先复用本次发现保存的页面，执行现有列表解析器。规则能读懂的页面不调用 AI。
3. 解析失败时调用单页 AI 协议：只返回列表区域、名称、标题/链接/日期等选择器。不返回代码，不决定任务调度，不要求用户提供网页证据。
4. 在原始 HTML 上执行规则，确认范围、标题和链接，并抽查公开正文与标题的对应关系。通过一个栏目即事务性保存栏目、规则版本、首批通知和后续采集任务。不等待第二次列表读取、分页或全校归属核实。
5. 后续 `collect` 复用规则更新、去重和补充历史页。改版修复与旧配置审核仍通过已有维护入口处理。

官网目录优先建立，已发现栏目随后接入，再继续展开其他单位。每读完一页就发布结构与派发栏目任务，避免首批结果等候整批慢页面。暂停、继续覆盖主任务和独立栏目/导航任务，保持原代次、已保存材料与模型执行记录；主动重试重新读取失败页，同一轮不会反复重开它。

## 部门与栏目结构

`Department.kind` 明确区分 `unit`、`group` 和 `column`，`structure_key` 提供目录节点稳定身份；`DepartmentDirectoryEntry` 保存层级及多处列示。栏目继续沿用原来的 ID、提取规则和通知关系。部门、分组不进入通知采集队列，没有栏目或没有官网链接的部门仍可先订阅。

`school_structure.py` 将当前官网目录及真实导航关系同步为订阅树。只有目录和单位网站能够支持的关系才挂接；跨学院友情链接不成为归属。同一部门的重名栏目保留本科、研究生等官网导航上下文，栏目原名与来源 ID 不被改写。目录再次同步保留节点、成员关系及既有订阅。

目录主体中的嵌套列表表达上下级，卡片标题表达官网分组；页头、页尾和全站菜单不作为该页的部门名册。同一页面同时包含桌面与手机目录时，合并同一父级下的同名分组及单位，保留各处原始出处，避免重复部门和重复订阅。

订阅页直接展示分组、部门、下属单位和栏目。整部门选择包含当前与未来栏目；取消其中一个栏目时取消覆盖它的上级勾选，保存明确的剩余选择。官网出处按需展开，尚无归属依据的栏目可以单独订阅，不假装已完成归类。

## AI 与程序的契约

单页输入包含候选编号、实际页面 URL、清理后的完整结构和可用标题信息。输出只有 `candidate_id`、`status`、`columns`、`reason`；`status` 为 `ready`、`not_column` 或 `unsupported`。每个栏目必须返回名称、列表/标题/链接/日期/正文选择器，以及栏目区域和标题定位。

分三层判定：JSON/字段合法；选择器可在原始网页上执行且只覆盖一个命名区域；真实通知样本匹配。AI 调用成功不等于接入成功。无效、截断、空匹配、混合栏目、虚构名称都不能写入栏目。AI 不提供目标地址，地址由已读取页面决定。超出输入容量的页面明确报告需要适配，不隐蔽截断后认定完成。

付费调用使用持久执行标识；恢复任务复用结果。网络重试由已有队列统一管理，不另加无限循环。首次不增加多轮自主探索；不能执行的输出作为该页面的失败结果保留。

## 状态与故障边界

产品显示正在查找、正在接入、已接入、等待重试、暂停、暂未找到或服务不可用。等待不显示运行中的动画。主信息是已接入栏目数，详细失败仅按需展开。AI 配置与复核工作不能成为普通订阅的必经页面。

学校任务完成表示本轮遍历结束，不表示所有学校网页已覆盖。栏目失败以独立任务记录错误，已接入栏目及通知持续可用。暂停阻止继续派发，正在执行的工作在安全边界保存。跨域来源继续遵守现有官网归属和公开地址约束。

## 兼容与落地顺序

1. 增加最小 AI 协议及执行测试，保留旧模式供已有任务使用。
2. 实现独立栏目接入与首次通知保存，复用现有队列；为准确区分部门和栏目增加迁移 `780c3f950e64`，只新增类型及稳定身份字段，现有记录默认保留为栏目，原 ID 和通知不变。
3. 将自动发现切换到新流程，取消首次订阅/重试对 AI 配置的强制要求；已暂停任务保持暂停，旧等待配置任务允许按规则继续。
4. 根据真实队列状态重写进度汇总和展示，保留兼容 API 字段。
5. 完成隔离数据回归、浏览器检查和可执行的官网抽查，记录未验证边界。

旧审核流程暂用于历史任务和人工配置，不对它做大规模删除；新自动接入不得调用该流程。历史通知及来源 ID 不变，已有来源不因本次发现而被覆盖或删除。部署前停服备份，发布使用完整版本；回退前保留新接入数据，旧版仍能读取相同的栏目与规则表。

## 验收标准

- 没有 AI 配置也能从官网导航接入规则可识别的栏目。
- 首次添加学校就能建立部门树；多级单位、没有链接的单位不能因为尚无可读栏目而消失。
- 同名栏目挂接正确，同院系不同业务的同名栏目可区分，跨单位链接不能误挂归属。
- 整部门订阅包含后续新增栏目；单独排除某栏目后，保存和刷新不能重新把它包含进来。
- 真实格式的模型返回经过协议层、解析层、接入层，最终生成可阅读通知；合法 JSON 但错误选择器不能通过。
- 新栏目接入不创建 `SourceProposal`，不重复获取列表做独立复核，不等待分页。
- 一个栏目不可访问或解析失败时，另一个栏目仍可完成；任务恢复不重复创建栏目、通知、规则版本或付费调用。
- 现有订阅、收藏、已读和有效配置保留；手动配置不能通过一个“已验证”标记绕过检查。
- 排队/重试与运行明确区分，用户无需配置 AI 才能重试。
- 自动化样本通过与真实官网抽查分开报告；未运行的真实 AI、浏览器或官网测试不得声称通过。

## 第一阶段接入链路验证（2026-10-02）

上述新流程已在源码中实现：`source_onboarding.py` 承担独立栏目接入，`column.schema.json` 定义 AI 输出契约，发现任务按页派发，首次订阅与重试均不再强制配置 AI。排队和等待重试不显示运行动画。已有数据及旧人工维护入口保留。

| --- | --- |
| 完整自动化回归 | 共 914 项，无失败，21 项按测试环境条件跳过 |

| 桌面浏览器 | Edge 的 1280、980、390 像素宽度通过，无脚本错误或横向溢出；另验证暂停、恢复及亮暗主题 |

第一阶段验收时交付范围为源码和方案，尚未打包。0.2.0 将这些改动纳入统一桌面发行流程；升级应先停止旧后台、备份原有数据，再整体安装新版，不能仅替换前端文件。
