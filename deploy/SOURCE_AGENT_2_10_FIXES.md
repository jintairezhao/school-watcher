# 2.10 来源读取与恢复修正

沿用 2.9 的聚焦探查、来源 Agent、持续采集和本地配置复用。本轮沿读取、分类、缓存、队列和规则验证的共同路径修复失败恢复；不增加模型额度，不扩展产品架构。

## 财政金融学院的 502 原因

同一环境、相同公开地址的实际对照：

| 读取路径 | 官网首页 | 用户给出的新公告页 |
| --- | --- | --- |
| 程序默认：环境代理＋固定公网 IP | 502，165 字节 | 502，165 字节 |
| 程序同样固定公网 IP，直连 | 200，78,181 字节 | 200，31,304 字节 |
| 代理接收主机名，仅用于诊断 | 200，与直连 HTML 哈希一致 | 200，与直连 HTML 哈希一致 |

域名公网解析、TCP 80／443 和 TLS 证书校验也成功。这次失败收窄为当前环境代理对 IP 目标的兼容问题，不能直接说学院网站不可用。响应中的 `Server: none` 在成功页面也存在，不能据此认定是谁生成了 502。

原程序仅为可选代理的 403／407 等错误保存换路恢复信息，漏了 502／503／504。修正后仍固定经过验证的公网 IP；保存问题和进度，在下一次持久网络重试时尝试直连。首次收到网关错误不会立即再发送一次请求，强制代理配置不绕过，直连收到的网关错误也不归因为代理。

实际公告地址为 `http://sf.ruc.edu.cn/sylm/gg_sy/gg/index.htm`。读取成功、正文身份验证和 AI 自动安装来源分别记录，不把诊断中的成功请求算作整校接通成绩。

修后实际持久任务完成“默认路径 502→保存 30 秒重试→下次直连 200”，两页保持原任务代次和尝试计数。验收先确认等待期内不能认领，再仅在隔离数据库调整到期时间，未实际睡满 30 秒；生产等待与错峰配置不变。最终闭环共 7 次实际 HTTP 读取，前置路径诊断和中止的隔离尝试另有 9 次，共 16 次；模型请求和 token 均为 0。

新公告的真实面包屑是“首页→首页→公告→全部”，程序识别到 20 条列表项。抽查的 3 篇正文分别显示“招生公告”“招生公告”“专硕教务”，标题、地址和日期与列表对应；这是官网“全部”的真实汇总，不能改名为独立“通知公告”。只记录实际观察到的附件地址，没有把附件地址记录说成已下载验证附件。

进一步试抓复现了另一个程序阻断：默认接入读取器没有使用已给出的正文规则，3 篇真实正文均在通用判定处被拒绝；同一保留材料用实际 `.articleDetail` 规则后，原正文与身份验证得到 3 条匹配。修正默认试抓时传递当前栏目规则；初次探索仍不带未经验证规则，自定义读取器保持原两参数接口。旧正文验证失败仅恢复保存的候选规则进行程序重验，不重新识别整个学校或清空付费请求。这个对照使用人工定位的真实规则，不冒充新的 AI 自动接入成绩。

## 同类失败的共同处理

跨流程受控检查还复现了动态错误被包装成普通字符串后丢失类型的问题：日常采集误创建规则修复任务，保存的材料被标为可用，随后可能再次进入 AI。共同修复入口现在使用相同的规则错误判定，快照保留原状态、错误、证据和等待信息；日常采集、旧版材料获取及任务重放都先区分材料、访问和规则问题。没有完整材料时先恢复读取，不重写提取规则。

明确的动态材料未完成使用已有的有限读取重试，保持原错误类型，默认共 3 次、延后 30／120 秒，错峰配置不变；用尽后才进入低频恢复，网站更长的等待优先。任务、缓存及完整材料恢复的回归验证保留旧规则、通知、订阅、已读和收藏；既有缓存机制不会把未完成动态材料当作可永久复用的完成页面。

试抓用途与提取规则独立传递，传入规则不会使探索试抓误走日常采集权限。受限的单篇试抓可以继续其他实际通知；日常访问保护保留。正文验证另增加可见文章主标题冲突的阻断：匹配的文档标题不能覆盖明确矛盾的真实主标题，另外两篇匹配也不能让这份规则安装；普通正文小节和网站标语不当成文章身份。

旧版任务迁移的受控费用检查证明：结果未知的旧事件可能被标为完成，再以新标识走到模型请求入口。本轮在迁移及新增模型动作前检查原账本，保留事件、调用标识和预留；未知结果暂停，已有成功输出只做程序验证，发送前已确认零消耗的失败仍可合法恢复。复现只使用模型入口桩，没有实际重复付费，不能说真实服务商已经重复收费。

这些约束及维护验收写入 [来源 Agent 说明](SOURCE_AGENT.md#失败恢复的维护约束)，回归通过现有 CI 持续执行。网络路径对照来自真实官网；上述跨层和费用边界属于本地受控实证，分别记录。

## 动态页面与受控恢复检查

人大本科招生页做了修正前后的完整生产路径读取：默认资源策略、真实导航限速与持久任务交接均未替换；没有屏蔽图片。45 秒预算下，修前 23.618 秒、修后 25.385 秒取得完整材料，两次的 29 个通知链接出现项（27 个不同标题／地址）和 5 个真实栏目入口逐项一致。修后观察到 79 个资源请求事件、44 个 HTTP 200 响应；其余 35 张图片在材料完整时尚未响应，不能算作完成读取。只有 1 次导航和 1 次主机令牌申请，任务同一代进度跨 15 次队列认领完成，最终访问令牌均已释放。这是相同默认读取预算的单页材料对照，模型请求均为 0。

此前按每个子资源额外等待 1 秒的诊断读法未能在 45 秒内完成，条件与生产导航限速不同。保留该失败，不能用它证明生产默认策略普遍失败，也不因此统一延长读取时间。

以下是程序边界的受控复现和修复，并非已证明这些情况在真实人大页面发生：

- 已确认动态加载后，渲染 DOM 删除加载脚本而仍有日期占位链接，不能提前判完整。
- 配置的目标区域本身存在占位链接时继续等待；其他区域未完成不能阻塞已经完整的目标。
- 读取总时限到达时，保留同一公开主文档中最后已验证的不完整材料及具体错误。取消、非法跳转、重新导航及超限不使用旧快照替代。读取预算与有界资源清理分开。
- 已完成的临时主机排队结果，在原等待时间到达后允许同标识重新执行；运行中、成功结果和普通轮询保持幂等。

实际材料与程序回归分别记录于 [本轮核对结果](../tests/acceptance/source_agent_2_10_checks.json)。本轮尚未完成整校同预算真实 API 对照及原要求的 5 所学校／50 个来源／100 条通知全流程验收；[先前验收与缺项](SOURCE_AGENT_ACCEPTANCE.md)继续有效。不得由单页成功推算人大新增来源数或所有异步网站的可靠性。

本轮没有新增真实模型请求、修改用户数据库或增加费用上限。2.10 安装包的字节数、MB 和 MiB 以本版发布资产分别核对，不沿用 2.9 的体积。

最终隔离完整回归运行 1,390 项：1,366 通过、24 项按环境跳过，无失败，262.727 秒。此前完整回归暴露的旧默认读取器测试桩参数不兼容已修正，并保留失败记录；没有因此放宽程序验证或费用保护。PostgreSQL、平台包与桌面流程仍由现有发布 CI 单独验收，不能把本地跳过项说成已在本地通过。
