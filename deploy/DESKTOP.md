# 桌面版与更新

桌面版复用现有网页与后端，使用系统网页引擎呈现在独立窗口中。关闭应用后停止网站、采集 worker、应用创建的采集浏览器和组件下载；不会关闭用户自己打开的浏览器。

## 下载和安装

[GitHub Releases](https://github.com/jintairezhao/school-watcher/releases) 提供 Windows x64 安装程序及便携 ZIP，以及 Apple 芯片、Intel Mac 两种 DMG。macOS 构建目标为 macOS 15 及以上。Windows 使用 WebView2，缺少该组件时安装程序会运行微软官方引导程序，首次安装需要联网。

首次启动直接进入通知页面，无需注册或登录，可直接打开系统管理。应用菜单可检查更新、查看采集组件、打开数据文件夹或退出。桌面窗口使用每次启动的本机访问凭据，保留写操作保护。源码与安装版共用同一入口，不再提供账号系统。

安装包不再内置完整 Chromium 和独立 headless shell。优先检测可用的 Edge／Chrome，使用独立临时配置，不读取用户浏览器历史、密码或登录状态。没有可用浏览器时，从 Playwright 官方下载源安装匹配版本的完整 Chromium（`--no-shell`）到用户数据目录；同时支持无界面采集和人工访问验证。只有 Safari 的 Mac 也需要下载。首次准备需要联网，下载失败可从页面提示或菜单重新检测，已有通知与设置继续可用。

全新安装不预选学校，也不包含开发者的通知、订阅和凭据。关注高校后自动查找公开通知，普通页面直接解析，特殊页面可选 AI 辅助；找到的通知立即可读，无需用户核实部门归属。失败页面与变化的读取规则会限频自动恢复，订阅页显示进度。升级隐藏未使用的旧版预设，保留已订阅或已有通知的学校与数据。

“按发布渠道”按照学校、实际发布单位或官网站点、栏目归集通知，显示通知数和未读数，并可查看各渠道的全部历史消息。详情保留每个已观察到的刊载渠道及其原文地址；同名栏目按实际来源区分。启用目录 AI 后，还会根据少量已抓取标题生成学生用途说明，复用缓存并遵循用量上限；浏览渠道不会触发 AI 调用。

栏目订阅页的进度区提供“暂停／继续”。暂停会等待当前页面或栏目检查保存结果，再停止后续发现；重启后仍保持暂停。继续沿用原任务的页面进度和 AI 调用记录，不重新开始整轮发现。

在系统管理 → 抓取任务 → 抓取设置中选择“起始发布年月”，默认本年一月。历史通知每批抓取几页后自动续抓；达到所选日期边界或官网末页才完成，不再把三页当作全部结果。修改年月不删除已有通知。Windows 右上角“…”菜单可检查更新、管理组件和打开数据文件夹。

系统管理 → API 用量是独立统计页面，展示近 7／30／90 天的 Token、调用次数、成功率、每日趋势和模型／用途分布。活动热力图展示近一年，窄窗口展示近 13 周；悬停、点击或方向键可查看每日数据。统计来自已记录的 AI 执行，连接测试单列，未知用量不当作零消耗，预留额度不计入实际用量；未记录的旧调用无法追溯补齐。每日图表按设备当前时区偏移汇总，月度额度沿用 UTC 月份；查看和刷新统计不会调用 AI 服务。AI 连接和额度配置仍在平台设置，统计页可通过“服务设置”直接前往。

| 系统 | 数据位置 |
| --- | --- |
| Windows | `%LOCALAPPDATA%\SchoolWatcher` |
| macOS | `~/Library/Application Support/School Watcher` |

安装目录只放程序资源，数据、密钥、浏览器会话和下载的更新留在上述用户目录。更新保留数据。Windows 卸载默认保留数据，也可主动选择删除当前应用数据、缓存和自动备份；手动导出的备份、自定义目录中的其他文件与迁移前副本保留。数据库升级前沿用现有自动备份逻辑。源码运行时原有 `data/` 不会被桌面版自动挪动；迁移历史数据请使用已有导出/导入或完整备份恢复流程。

## 文件位置与存储

Windows 首次安装可选择程序、数据、缓存、备份和更新包目录；已有数据位置会作为默认值。普通升级自动继承原程序目录和全部文件位置，保留快捷方式设置，不再显示目录选择页。默认缓存与数据同目录，自动备份和更新包分别在数据目录的 `backups`、`updates` 下。

安装后打开系统管理 → 存储管理 → 文件位置，更改目录时选择空文件夹。迁移窗口依次显示保存进度、关闭服务和迁移校验；抓取任务停止领取新工作，在当前安全边界保存进度，后台服务确认退出后才复制文件。成功后切换位置并重启，未完成的任务从保存的进度继续，原目录保留为副本。

等待保存时可取消；等待超时会放弃本次迁移并恢复原位置的抓取。导入、导出或组件安装正在进行时需先完成这些操作。复制失败时原配置继续有效，重新打开后继续使用原数据。目录配置在 Windows 使用当前用户注册表，在 macOS 使用默认数据目录中的 `desktop-locations.json`；请不要手动移动这些入口配置。

主动更改程序位置时，应用下载正式安装包并校验后打开完整向导；此操作与普通升级分开。macOS 在 DMG 或 Finder 中选择 `.app` 的位置；缓存、备份和数据位置同样可在存储管理中更改。

各类缓存可在对应行清理。保留天数、容量（MB）及自动备份份数均可填写非负整数，0 表示不限制。通知目录和收藏正文不随缓存清理删除，活动任务与栏目依赖的证据受保护。手动导出的数据备份保存到所选备份目录，不参加自动轮转。

## 检查更新

每次正常启动后在后台检查一次正式发行版。有新版时在窗口右下角提示“查看更新”；选择“稍后”后本次启动不再提醒，下次启动重新检查。网络不可用或没有新版时不弹窗，不影响阅读和抓取。自动检查不下载或安装软件。

菜单 → 检查更新 → 下载更新 → 立即更新。只查询正式版本，不降级，未经确认不安装。按当前应用架构选择安装包，下载大小及 SHA-256 均通过后才允许打开安装程序。macOS 仍需在 DMG 窗口中拖动替换应用。

Windows 安装版确认更新后，先关闭后台服务并释放数据锁，再启动原地升级。升级界面只显示进度，完成后自动重新打开；不重新配置或迁移个人数据。手动下载并打开新版安装包时，也会识别原安装位置并跳过首次安装页面。需要主动重选位置时使用存储管理中的程序位置入口。便携版转为安装版时仍保留完整向导，不会静默覆盖另一份安装。

更新源是本仓库的 `/releases/latest`。私有仓库阶段，普通安装者无法查询更新；仓库公开后该功能即可面向公众使用。应用内不嵌入 GitHub 访问令牌。网络不可用、请求限流或校验失败不会影响已安装版本。

## 开发与打包

Windows 和 macOS 必须在相应系统构建。Python 3.14.3：

```sh
python -m pip install -r requirements/build.txt
python desktop/entry.py
```

运行 `python desktop/build.py`。构建不需要下载或收录浏览器。Windows 安装包需要 Inno Setup 6.6 或更新版本 和微软 WebView2 官方引导程序的本机路径 `WATCHER_WEBVIEW_BOOTSTRAPPER`，使用 `python desktop/build.py --installer`。CI 单独下载 Chromium 用于验收，但不放入安装包。

生成内容只在 `.local/desktop-build`、`.local/desktop-dist`、`.local/desktop-release`。资源收录使用明确目录清单，不收录仓库根目录、`.env`、`data/`、`.local/` 或宣传片。完成后检查最终文件树，拒绝私有数据库和媒体制作文件。

## 发布新版本

1. 修改 `desktop/__init__.py` 的 `VERSION`（例如 `0.2.0`）与 `desktop/RELEASE_NOTES.md`。
2. 将变更合入 `main`。Desktop builds 会完成三个目标的构建、浏览器的有界面／无界面模式和原生窗口启动验收。
3. 所有目标通过后，工作流为尚未发布的版本创建对应标签和 Release，上传三个安装包、便携 ZIP 和统一的 `SHA256SUMS.txt`。已有版本不会被覆盖；也支持主动推送 `v0.2.0` 这样的版本标签触发发布。

不要单独覆盖某个已发布安装包而遗漏校验文件。检查更新依赖文件命名规则，请通过构建脚本生成。

正式广泛分发前建议配置代码签名：Windows 安装包签名与 Apple Developer ID 签名、公证是独立发布步骤。当前工作流没有私钥和公证凭据；未签名构建的系统提示需如实告知下载者。不要通过全局关闭系统安全检查解决安装提示。
