# 存储管理与通知合并

管理员访问 `/admin/storage`，可自填正文和网页缓存保留天数、容量（MB）、抓取记录保留天数及自动备份份数。0 表示不限制对应项目。各类缓存、自动备份和已结束记录可以在用量表的对应行清理。规则保存到数据库，网页和独立后台进程共同读取；保存规则本身不会执行清理。抓取记录设置与原抓取记录页面同步。

手动清理可选择按已保存规则清理，或清空所有未收藏正文及调查网页缓存；两种方式都会清理超期已结束记录和超出保留份数的自动备份。清理前有明确确认，收藏正文、通知标题/日期/原文链接、用户、订阅及正在运行的任务保留。数据库空闲空间可供后续写入复用，文件大小不一定立即减少。

「导出数据备份」下载 ZIP，包含学校、部门、通知、已缓存正文、摘要及来源/目录关系，不包含账户密码、配置密钥、个人收藏或阅读状态，也不下载未缓存正文、图片及附件。需要保留旧正文时先导出再清理。原有每日完整数据库备份继续独立运行。

导入、导出显示分阶段进度、已处理量、速度与耗时。文件读取和写入使用 B/s、KB/s 或 MB/s；数据库校验和合并显示条/s。传输完成后仍会继续显示校验与合并进度，数据库事务提交后才提示完成。桌面版导出直接保存到选定的备份目录；网页版显示传输到浏览器的进度，最终落盘由浏览器下载功能完成。

「导入并合并」支持上述 ZIP 和原有 `watcher-*.zip` 自动数据库备份。界面不再固定限制 100 MB 上传；“导入选项”中可调整允许的展开大小，默认 1024 MB。按选定文件大小设置本次上传额度，解压前检查展开大小和临时磁盘空间。JSON 按记录解析并暂存磁盘，不把整份正文一次性加载到内存；路径、文件数量、单字段、关系完整性、HTML 与数据库安全检查继续保留。每表记录预算随展开额度增长（至少 20 万行，额度每 KB 对应一行）。同一实例同时处理一份导入或导出，断开连接时中止尚未提交的合并。

网页版还受部署时的反向代理和服务器请求体配置约束；扩大导入额度时应同步调整这些配置。无进度协议的旧 API 保持原来的 100 MB 上传、256 MB 展开默认值。

按规范化原文链接去重，保留有实际含义的查询参数及网页应用路由；无链接记录按学校、部门、标题和发布时间（缺失时使用创建时间）匹配。重复项保留当前内容并补全缺失正文、摘要、日期和来源关系，历史独有通知追加，当前独有通知保留；不按当前官网列表筛除历史记录，不按备份中的编号覆盖新库。新导入学校不会自动订阅。校验失败不写入，合并过程中数据库错误会整体回滚。完整恢复账户及运行目录请使用完整实例备份流程。

无链接且发布时间、创建时间均缺失的历史记录，使用内容指纹辅助去重；备份会保留该指纹，因此清理正文缓存后再次导入仍可匹配。

账号、订阅和个人状态的完整搬迁与恢复见 [部署与维护](README.md#完整搬迁与备份恢复)。
