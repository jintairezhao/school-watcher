# 官网信源探索整改计划

更新：2026-10-16。当前基线：2.21（`cea6c9dd`）。用户已授权按本计划实施；验收通过前不把实验能力描述为已完成接入。

目标：以本科生、研究生和教师的有限共享需求为探索先验，先观察官网主干，在同一探索轮覆盖主要需求。专用 Agent 发现和修复，程序实际验证并持续采集，成功配置本地复用。来源继续呈现为“学校 → 真实部门 → 真实栏目”。

范围补充：本轮修改官网框架结构探索、信源发现与接入。正文抓取、正文布局和附件提取保持原样；用户后续授权一并修复发布时间元数据识别；接入验证继续复用现有列表和正文抽检，不以本轮为由重构文章读取链路。

费用整改优先：早期实际费用未达预期，保留真实账本、原始失败和未知付费结果。已执行五校两臂受限实网对照，每臂最多3次新增请求/32,000 token（含预留）/480秒活动窗口，继续受用户已保存限制约束；此前独立失败和额外阶段分别登记。不得重置预算、重发未知执行，或把材料减少当作实际省费。完整结果及未通过门槛见当天结果报告。

## 已有基础与本轮边界

- 复用：首页当前证据支持的院系／学科目录优先、持久待办、切片轮转、共享限速、学校共同预算、菜单角色缓存、来源验证、规则版本和稳定来源身份。
- 已知缺口：主干初次读取以后，固定栏目／学生关键词优先仍可能让局部分支拥挤；共享画像、按真实范围区分的需求覆盖、验证过的路径反馈和可解释选择记录需要补齐。
- 2.21 的真实初轮对照是 2 个来源对 7 个独立栏目，实际 token 总量增加。不能据此承诺等覆盖成本下降。最终代码尚未完成新的五校整轮付费验收。
- 不增加独立渠道页面、逐项事实确认、多 Agent 产品框架、云端来源库或默认本地模型。Crawl4AI 不默认捆绑浏览器，不自动换服务商。

| 阶段 | 工作 | 可核对的产物 |
| --- | --- | --- |
| 1：基线与观察 | 冻结当前排序作为对照；记录候选、当前材料、选择原因、真实请求及未知成本 | 只读来源图回放、选择记录、分支成本关联 |
| 2：需求与覆盖 | 本科生／研究生／教师可组合画像；按真实导航范围 × 需求类别区分已探测和已验证 | 集中配置、纯策略模块、同轮覆盖调度与重启回归 |
| 3：辅助反馈 | 信息觅食辅助深入／换分支；上下文图复用真实成功路径 | 验证收据只读复用、当前有效路径与保守反馈 |
| 4：Crawl4AI 优先对照 | 独立固定版本对照动态读取、材料完整度和探索效果 | 可复验适配合同与对照工具，清楚区分离线回放、本机浏览器和真实官网 |
| 5：接入验证 | 复用现有抽检确认栏目／归属和接通；验证探索中断恢复、已有来源继续更新；相同预算比较 | 真实结果、遗漏原因、参数验证状态；验证通过后按既有要求发布 |

## 策略约束

1. 画像定义需要什么，官网证据定义可以去哪里。画像不提供学校或部门事实，不按网址前缀／名称猜归属；学校共用官网、独立校区、同名单位保持独立证据和身份。
2. 先读取真实学校入口及当前导航支持的主干目录；然后结合覆盖缺口分配切片，在同类需求候选内使用路径线索和读取收益。保留最旧入口轮转，所有正常待办持久保存，无统一全校页数截断。
3. 需求类别起始包括院系专业、教学培养、升学、奖助、就业、竞赛交流、科研学术、人事发展、校园事务。权重只是排序启发式，不是概率／覆盖百分比。学生和教师的组合不要求用户逐项配置。
4. 覆盖的基本单元是有证据的探索范围 × 需求类别；一个学院不代表所有院系，一个校级奖助来源不代表各学院奖助。读取过网页与程序验证接通分别记录；材料不足和未知范围保持未知。
5. 信息觅食使用程序确认的新材料、实际有效入口及接通结果；解释措辞、通知条数、重试次数不能冒充收益。没有实际 token／耗时关联时明确成本未知，不伪造收益率。
6. 路径记忆只沿当前 hash 对应的真实前向链接传播；循环、陈旧链接、歧义父链及跨校／配置变化不得借旧信用。成功不会让同目录下所有学院自动成为高收益分支。
7. 502、连接失败、访问受限、材料未完成、规则错误和空栏目分别处理。网络失败不降低语义相关性，不触发整站重识别。无新通知不等于规则失效。
8. 新规则仍经实际列表范围、真实名称、正文身份、原文地址、发布时间、附件和实际存在的分页验证后安装。修复不改变来源编号、订阅、已读、收藏或通知的多来源关系。
9. 预算沿用已有用户覆盖。默认每校同轮 40 次实际请求／200,000 token；发现、接入和修复共用，缓存不计费，未知付费执行不自动重发。切片、重启、改画像不重置预算。

## Crawl4AI 的决策门槛

- 同时评估其网页读取／材料处理能力和探索策略，不能把它描述为仅下载器，也不能把 AdaptiveCrawler 的问题回答充分度当成学校来源接通率。
- 首先固定版本在隔离环境复用系统 Edge，对同一官网导航、院系目录、异步菜单、多层入口和同页多栏材料比较真实浏览器结果。随后才能比较相同官网、同样费用预算下的来源发现和接通；不扩展为正文抓取对照或改写。
- 适配必须继续经过既有 URL 和子资源检查、跨进程共享限速、总时限、3 MiB 上限、缓存与恢复。未满足条件时保持诊断用途，不接入默认生产读取。
- 不默认逐页 LLM 提取、语义向量模型或额外付费服务。保留原 HTML、链接附近文字及定位，内容清洗不得删除发现阶段所需的导航。
- 独立报告读取完整度、已验证来源、时间、实际 token、资源与冻结打包结果。解压依赖体积不等于 setup.exe 大小。

## 参数和验收

既有网络、切片、模型输出和预算起始值沿用集中管理及用户覆盖。新增画像类别权重从相同权重起步，全部标记“尚未跨高校实测”；不凭一次回放设定生产最优权重。每四个模型决策检查进展、连续两个无进展窗口停止当前分支的机制继续复用。

真实验收至少五所不同结构高校、五十个已确认真实来源、一百条通知，其中至少两所不参与本轮调参。调参应覆盖人大、中石克校区及交大的已知问题；独立验证学校另行冻结样本，不能回头调参后继续冒称独立。

在相同配置与预算下记录：各需求及部门首次接通时间和覆盖增长；每个遗漏原因；栏目／原文／部门／日期正确性；实际页面读取、模型请求、服务商 usage、时间和缓存命中；预算停止、网络限制与判断错误；新增通知、改版、中断恢复和无新通知行为。费用受限／条件不足时保留进度并明确未完成项，不用模拟结果代替真实验收。

交付参数表区分“已实测保留、实测后调整、尚未验证”。Windows x64 setup.exe 约 100 MB 为软目标，报告实际字节、MB、MiB；其他平台分别评估。未通过完整验收前不宣称完成全部整改。

2026-10-16 补充范围：用户明确同意修复发布时间元数据识别。仅调整标题与发布字段的观察和旧未知日期的重新核对，不修改正文内容、附件读取或收藏材料。日期、来源接通与部门归属分别验收；没有日期证据时保持未知，不从活动时间、网址、更新时间或当前年份补全。
