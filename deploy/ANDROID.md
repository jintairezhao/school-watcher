# Android 版

Android 客户端位于 `android/`，使用 Java、Android Views 和 Material 3，支持 Android 8.0（API 26）及以上。这是在手机独立保存数据、读取公开官网的首版，不需要连接电脑或注册账号。

## 使用

1. 安装构建得到的 APK，打开「学校通知」。全新安装没有订阅或示例通知。
2. 在「订阅 → 添加订阅」搜索学校，连接官网查找通知栏目；也可输入学校名称、栏目名称和公开列表地址。
3. 找到有日期的通知列表后，选择「订阅当前栏目」。采集状态和失败原因在订阅列表显示。
4. 在「通知」手动刷新、搜索、筛选或补抓历史，打开通知后可收藏、分享或跳转官网。成功读取的正文及表格自动保存在手机供离线阅读。
5. 在设置中选择主题、后台刷新、网络条件和新通知提醒。后台刷新默认关闭，开启后可通过「系统后台与电池设置」允许「学校通知」不受电池优化限制；等待授权或系统限制后台时，仅在打开应用时采集。授权后约每小时尝试检查一次，实际执行仍受系统网络、电量及厂商策略影响。提醒权限独立于后台设置，拒绝提醒仍可正常阅读。

暂停订阅、官网撤文和采集失败不会删除既有通知。清理离线正文不删除通知索引、订阅或个人状态。当前没有导出或跨设备同步，卸载应用会移除其本机数据；系统云备份关闭。

0.1.3 修复手机搜索时键盘将底部导航顶起的问题：贴底键盘弹出时隐藏底部导航，收起后恢复；搜索文字保持不变。宽屏侧边导航和不占底部空间的悬浮键盘不受此规则影响。

0.1.3 同时补入中国石油大学（北京）克拉玛依校区的独立目录入口，可搜「中石克」「克拉玛依」「中石大克拉玛依」或官网域名。学校名称和地址依据[校区官网](https://www.cupk.edu.cn/sy/index.shtml)核对；搜索也包含原有目录的学校简称，并兼容中英文括号。

## 历史通知、筛选与手机正文（0.1.4）

- 「通知」和「收藏」均可点击「筛选」，设置发布日期起止范围（含首尾两天）、学校、栏目、已读/未读以及最新/最早优先。支持最近 7/30/90 天、本年和不限日期，应用后的选择会保留，重置可恢复全部条件。关键词仍可与这些条件组合。
- 筛选针对已下载通知。列表显示实际匹配总数与当前显示数量，「显示更多已下载通知」仅展开本地列表，不会用显示上限冒充通知总数。
- 新订阅或升级后的现有订阅首次尝试读取各栏目最多 3 页。正常刷新继续检查最新列表；「补抓历史」按当前学校和栏目范围，为启用的订阅继续读取最多 5 页。日期、关键词、阅读状态用于本地筛选，不会限制补抓页内保存的记录。
- 每个历史页的通知和下一页地址在同一事务中保存。中断或失败不跳过当前页，重新打开或重试可以继续；原有收藏、已读和缓存不受影响。重复点击不叠加未完成批次；单次工作最多处理 150 页，未完成任务可继续补抓。只跟随官网明确的同源下一页链接，遇到末页、重复链接或无法识别的分页时停止，不承诺一次下载全站历史。
- 正文保留段落、标题、列表、超链接和表格行列、合并单元格，移除官网固定宽度、脚本和内联样式。正文适应屏幕；宽表格在自己的区域左右滑动，支持深色和系统大字体。图片及附件通过用户点击在浏览器打开。
- 阅读器只显示已清洗的本地内容，不允许网页脚本、网络资源请求、文件或内容提供器访问；这不是动态网页采集功能。排版缓存与 WebView 自身数据均在应用私有目录内，清理正文同时清除文字及排版缓存，普通卸载移除全部应用私有数据。
- 旧版文字缓存首次联网阅读时升级为有结构的正文；离线时仍可读旧缓存，并提示联网恢复排版。数据库升级保留既有订阅、通知和个人状态。

中石克内置 42 个经实抓核对的公开栏目，包括校区通知、教务及其子栏目、学工、资助、团委动态、研究生及各学院通知。在「订阅 → 添加订阅」选择校区即可看到列表，支持单独订阅或「订阅全部 42 个栏目并抓取」。这是用户主动抓取，使用当前网络；之后的自动检查遵循 Wi-Fi 开关。重复订阅不会复制栏目或丢失已读、收藏和正文；不预先添加个人订阅。校区分开显示年份和月日的列表已做专门适配，以页面标注的日期为准。栏目名称和官方 HTTPS 地址维护于补充文件的 `presets` 中，并随公共目录导出；无需读取桌面个人订阅或运行数据库。

「自动抓取仅用 Wi-Fi」默认开启：后台定时检查和回到应用时的自动续抓都只允许 Wi-Fi。关闭后两者都可以使用 Wi-Fi 或手机流量；这不会自动打开后台刷新权限。无符合条件的网络时保留进度并提示等待，回到应用或应用可见时网络恢复后按原间隔规则继续。手动点击刷新可使用当前网络。Wi-Fi 按网络类型判断，不把“不计费流量”误认成 Wi-Fi；自动请求及 DNS 使用选定网络，不在连接失败时自行切换到其他网络。混合 Wi-Fi/蜂窝的 VPN 在仅 Wi-Fi 模式下暂停，以避免使用手机流量。

## 干净卸载（0.1.2）

普通卸载应清除应用自身的数据和运行任务。所有订阅、通知、收藏、已读、离线正文、设置、抓取断点及 WorkManager 数据均在应用内部私有目录；不在共享存储根目录、下载目录、相册或其他应用中创建自动备份或隐藏副本。不依赖应用收到卸载通知后再执行清理：卸载由 Android 删除应用私有存储并移除其任务和通知。参考 [Android 应用专属存储](https://developer.android.com/training/data-storage/app-specific)。

- 禁用系统自动备份，并分别配置 Android 11 及以下、Android 12 及以上的全部数据排除规则；后者同时排除云备份和设备迁移，包含设备保护存储。不配置自定义备份代理。参考 [Android 备份控制](https://developer.android.com/identity/data/autobackup)。
- 显式设置 `hasFragileUserData=false`，不请求系统在卸载时提供保留应用数据的选项。没有独立守护程序、额外安装包或设备管理权限。
- 重装应从空订阅、空通知、默认设置开始，后台刷新默认关闭。升级安装则保留原有数据，不等同于卸载。
- WebView 的网页缓存、Cookie 和会话均保存在应用私有目录；后续接入下载或日志功能也须遵守此存储边界。添加新组件时重新审核最终合并清单和它的文件写入位置。
- 用户主动下载的安装 APK、在浏览器下载的附件、分享给其他应用的内容由相应应用或用户管理，不属于本应用可清除的私有数据。系统归档（保留数据以便恢复）也不等同于普通卸载；不能承诺删除厂商系统日志、用户自行制作的备份或其他系统持有的历史记录。

卸载验收使用专用、可重置的 Android 模拟器，检查卸载前存在的数据库、设置、缓存和待执行任务；普通卸载后确认私有目录、安装目录、活跃任务和通知消失，再重装确认旧数据未恢复。vivo / OPPO 等厂商系统还需按同一流程进行真机验收。

可重复验收脚本为 `scripts/android/check_uninstall.py`，仅接受专用、可 root 的模拟器和显式 `--allow-reset` 参数，会覆盖该模拟器中本应用的数据，并访问一个公开学校栏目生成真实通知。通过 `--adb`、`--serial`、`--apk`、`--output` 指定工具、设备、安装包与报告目录。它检查可执行任务，不将系统保留的“最近完成任务”诊断历史误当成仍在运行的应用。

## 中断与恢复（0.1.1）

- 每次回到应用时检查上轮开始时间。距离上轮开始已满一小时，开始新一轮检查全部启用栏目；未满一小时，继续未完成栏目；全部已完成则等待下个间隔。手动刷新在本轮完成后可提前开始新一轮。
- 每个栏目的通知、检查结果与进度在同一数据库事务中保存。系统杀进程、强行停止或授权撤销不依赖退出回调保存进度；中断中的栏目重新请求，已完成的栏目跳过。新一轮也不会清除历史通知、已读、收藏和离线正文。
- 关闭后台开关、撤销电池优化豁免或系统标记为后台受限后，应用退到后台会暂停采集。正在传输的请求在下一次检查授权时退出（阻塞的网络读取受超时限制），不会把未完成请求标记为已完成。暂停的订阅不再提交结果。
- 强行停止后由系统停止应用，直到用户再次打开。设备重启后的后台调度由 WorkManager 恢复，仍需满足授权和网络、电量条件；不会用保活服务或闹钟绕过强行停止。
- 最新通知检查的断点粒度是栏目当前列表页；0.1.4 为历史翻页另加持久化的页断点，不包括动态网页或正文下载。网站读取失败会记录原因，并继续其他栏目；失败栏目可手动重试或在下一轮重试。
- Android 的电池优化豁免不等同于永久后台权限。vivo / OPPO 等厂商的额外自启动、后台活动设置无法全部统一读取；应用提供系统应用信息入口，实际效果仍需对应型号真机验证。参考 [Android 电池优化说明](https://developer.android.com/training/monitoring-device-state/doze-standby)。

## 本版边界

- 内置 201 个学校与校区官网入口，来自公共学校目录及 Android 校区补充文件，没有预选学校。目录不代表所有网站已验证适配。
- 当前解析静态 HTML 的带完整日期通知链接，每页最多识别 150 条，并支持上述有限批次历史翻页。栏目发现由用户沿官网链接逐级选择；没有桌面端的完整自动发现及全部专用适配器。
- 动态接口、JavaScript 渲染、验证码、登录网页以及无法识别的列表会显示错误或无结果，需在浏览器中打开。不会将空结果当成成功清空记录。
- 阅读器缓存已清洗的正文与表格，原文图片和附件通过外部浏览器查看。未识别到正文时提示打开原文；对不支持的网站不能保证排版与官网完全一致。
- AI 摘要、桌面数据库互通、备份导入导出暂未接入。
- 后台提醒由手机检查结果触发，不是服务端即时推送。强制停止应用、系统限制后台或断网时不会保证定时运行。

## 构建

安装 JDK 17、Android SDK Platform 35 和 Build Tools 35.0.0。通过 `ANDROID_HOME` 或不入库的 `android/local.properties` 指定 SDK 目录。

Windows：

```powershell
cd android
.\gradlew.bat :app:testDebugUnitTest :app:lintDebug :app:assembleDebug
```

macOS / Linux：

```sh
cd android
bash gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleDebug
```

安装文件：`android/app/build/outputs/apk/debug/app-debug.apk`。调试包用于本机测试，正式分发需维护者自己的长期签名密钥；仓库不包含密钥，也不会自动发布商店版本。`assembleRelease` 默认生成未签名版本。

Gradle Wrapper 与发行包固定为 8.11.1，发行包下载带 SHA-256 校验。构建配置使用 AGP 8.9.2、compile/target SDK 35。版本兼容依据：[Android 官方 AGP 8.9 说明](https://developer.android.com/build/releases/agp-8-9-0-release-notes)。

`.github/workflows/android.yml` 执行检查并保存调试 APK，不发布 Release。修改学校目录后运行 `python scripts/assets/android_catalog.py`，生成过程不读取运行数据库或个人订阅。

Android 独立校区补充项维护于 `config/android-school-supplements.json`，简称同时读取公共目录的别名映射。CI 使用 `python scripts/assets/android_catalog.py --check` 确保补充项和简称实际进入安装包，避免只改目录源却遗漏打包。

## 验证与发布前检查

单元测试覆盖静态解析、无效链接、日期归属、正文清洗，以及数据库增量合并对收藏、已读、旧通知和缓存的保留。Android lint 检查系统版本兼容和资源使用。

0.1.4 验收：48 个测试通过，lint 无错误（8 个警告）。Android 15 模拟器覆盖安装后数据库从版本 2 升至 3，旧收藏、已读及缓存保留；42 个栏目历史首批共读取 106 页，通知从 378 条增至 871 条，无读取失败。选中教务栏目补抓 5 页后，该栏目由 30 条增至 80 条，其他栏目进度不变；验证日期、学校、栏目、阅读状态和排序组合，以及重启后筛选保留、本地列表展开至 200 条。

正文验收使用官网实际表格，保留 9 行、63 个单元格：手机正文宽度与视口一致，只有宽表格可以横向滑动；深色、系统大字体、平板和完全断网后的缓存阅读均通过。新增阅读器实际产生私有 WebView 数据后，再执行普通卸载，确认私有目录、运行任务、通知及进程消失；重装后订阅、通知、最新检查及历史页断点为空。上述结果来自 AOSP 模拟器，尚未替代 vivo、OPPO 真机验收。

0.1.3 验收：35 个测试通过，lint 无错误（7 个现有警告）；目录导出一致性通过。使用 Android 15 模拟器验证内置 42 个中石克栏目一键订阅，实际读取 378 条栏目列表记录、无读取失败；仅 Wi-Fi 开启时移动网络自动抓取不推进断点，关闭后自动续抓成功。另验证手机通知/收藏搜索的键盘显示与隐藏、搜索文字保留、深色及大字体、宽屏竖屏侧栏显示。卸载存储边界沿用 0.1.2，未新增外部文件写入；本次不重复卸载验收。vivo、OPPO 真机及第三方中文输入法仍需实机复核。

恢复测试额外覆盖持久化后重开数据库、间隔边界、授权撤销、完整轮次不重复请求、手动重试、订阅变化、过期任务回写、存储失败的事务回滚、旧版数据库升级，以及系统时间回拨。

发布前还需在设备检查：Android 8 与 Android 13+ 的首次运行和拒绝提醒权限、手势返回、旋转、深色主题、大字体、离线正文、暂停恢复订阅及后台省电行为。构建和本地测试通过不能替代真机验收。

应用内「设置 → 许可与第三方声明」包含项目许可和随应用使用的组件许可。
