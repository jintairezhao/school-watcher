# 官网来源完整性目标

当前目标覆盖项目高校目录及用户补充的学校，已订阅学校优先处理，不将学校范围缩成几个示例。用户于 2026-09-21 明确调整重点：逐校深挖院系设置中的专业，以及教务、培养、选课、考试等学生关心的实际通知来源，不再以全站宣传信息为主要目标。历史全站缓存保留，不能用其规模或新闻栏目通过数代表学生相关来源的覆盖率。

## 验收标准

1. 院系、专业、教务及相关教学管理单位分别建档，保留官网名称、上下级关系、入口和出处。没有识别出通知列表的单位不能从框架中消失。其它已发现单位保留参考，不占主要采集资源，不将其未访问页面混入学生范围的验收分母。
2. 一个单位可以有多个网站、多个发布栏目，一个页面可以有多个官网入口。链接去重不能丢掉来源名称和隶属关系。
   父子关系必须有官网嵌套结构、明确栏目标题或单位官网自身的证据。发现页面链接到某单位，不自动等于组织上的上下级。保留分组、单位与栏目三类节点以及多处挂载，不按名称前缀或 URL 路径推断行政隶属。
3. 发现从首页、机构目录、院系和专业目录、站点导航及相关下属站点继续展开，优先教务与学生相关栏目。学院内混合新闻栏目可能包含教学通知，不能仅按“新闻”字样丢弃。分页、折叠菜单、脚本入口、跨域官网、旧站/新站并存及没有链接的单位名单都需要留证或标明待适配。
4. 无法访问、无日期、长期未更新、明确停用分别记录。一次请求失败不等于废弃；陈旧页面仍保留入口及证据，不自动删除。
5. “匹配度达到 90%”围绕上述学生相关范围至少同时满足：
   - 单位与专业覆盖率：独立核对的官网院系、专业及相关教学管理基准清单中，已准确映射的条目占比 ≥90%；
   - 发布栏目覆盖率：逐相关单位核对的官方通知来源基准清单中，已准确映射的栏目占比 ≥90%；
   - 来源准确率：已接入的学生相关来源中，官网名称、发布单位、原始入口及栏目范围核对一致的占比 ≥90%。
6. 不能以“爬到的链接都写进库”或“学生优先队列已空”证明覆盖率。学生范围本身也要独立复核，不能仅按优先级关键词决定验收分母。没有独立基准、相关范围尚有未核实的目录页、脚本菜单或失联入口时，不得显示通过。不能通过删除相关失效/陈旧入口来提高分数。
7. 每校提供证据时间、页面快照摘要、发现路径、候选和已核实状态、未解决项及复查记录。抓取预算用完或进程停止后可继续，不能把截断当成完成。

## 现状根因（2026-09-19）

- 首页轻量发现只返回前 12 个栏目；
- 旧深度发现最多 30 个顶级单位、每单位 8 个子项，后台另一套流程又截断到 60/90；
- 多组黑名单排除图书馆、招生、招聘、采购、信息公开等真实信息来源；
- 单位识别与栏目识别混为一体，没有匹配出列表的单位被略过；
- 以同名或单个列表 URL 去重，可能吞掉同名栏目及多个真实入口；
- 没有可复查的基准、发现图谱、失效证据和持久化待处理队列。

后续实现和验收必须使用这里的完整目标。自动发现进度与最终 90% 验收分开展示。以下历史记录中的 99% 是调整前的目标；当前验收以本节及程序统一阈值为准。
