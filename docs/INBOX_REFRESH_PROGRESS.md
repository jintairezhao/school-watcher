# 收件箱刷新与进度恢复

页面同步与官网抓取分开。刷新按钮只读取数据库中已保存的目录和通知；官网抓取由独立采集进程执行。离开收件箱、切换收藏页或暂时断网，不取消已经入队的任务。

## 抓取间隔与权限

- 首次打开收件箱和浏览器整页刷新仅调用一次 `POST /api/inbox/sync`。服务端按系统管理保存的 `scrape_interval`（分钟）检查全部订阅来源，未到期不入队。
- 新鲜度使用共享来源的最近成功抓取时间、最近任务尝试完成时间，取较新值。失败尝试也受间隔约束；活跃任务直接共享。不使用每个浏览器自己的计时器，避免用户间重复抓取。
- 普通刷新按钮、学校及栏目筛选、切换视图和历史返回只读取数据与进度。普通用户调用手动抓取接口会收到 403。
- `POST /api/inbox/refresh` 仅允许管理员手动抓取当前范围或全部订阅，可以越过常规间隔；活动任务及一分钟内的重复请求仍去重。
- 后台定时采集使用同一间隔。任务重新入队时在数据库条件中再次检查间隔，避免并发请求用过时的状态重复安排刚完成的任务。
- 同步检查保留原进度响应，另有 `scheduled` 表示本次需跟踪的来源数量（含共享活跃任务）；均未到期时不写入新的跟踪指针。

## 持久状态

- `app_config` 的保留键 `inbox_refresh:user:{id}` 每用户只存一条刷新范围指针：来源编号、范围和开始时间。无需新增表，不保存正文或进度副本。
- `GET /api/inbox/refresh?resume=1` 依据当前登录用户恢复范围，并与其当前订阅求交集；进度始终读取原有 `BackgroundTask`。
- 局部更新与未结束的更新范围合并。并发标签通过有限次数的比较后更新避免互相覆盖；来源采集仍走原有去重任务。
- 返回页面、历史返回、恢复标签可见性和网络恢复只查询进度。浏览器整页刷新会检查抓取间隔，存在活动任务时继续跟踪；没有活动任务且来源未到期时不重复抓取。
- 暂时查询失败会退避重试并保留最近确认的进度。未确认送达的刷新请求明确提示重试，不使用旧任务的完成状态冒充本次成功。登录或权限变化会停止查询。
- 进度接口使用 `Cache-Control: no-store`。读取进度不会新增采集任务。

## 界面

常用搜索和通知列表刷新保留在工具行，搜索文字相对整个搜索框居中。时间、年月和已读条件在“筛选”浮层中；批量已读与重置在“更多操作”中，管理员还可在其中选择“抓取当前范围”或“抓取全部订阅”。条件摘要一直可见，浮层不改变列表高度。状态条只占一行，具体来源状态点击展开。

## 验证

- `tests/test_inbox_refresh.py`：范围恢复、用户隔离、订阅变更、任务去重及局部与全局合并。
- `tests/test_refresh_tracking_concurrency.py`：真实 SQLite 并发标签范围写入。
- `tests/test_collection_admission.py`：间隔前后、失败间隔、管理员权限、共享来源及并发入队。
- `tests/check_inbox_toolbar_browser.py`：桌面／手机、浅深主题、浮层键盘操作、网络恢复、离页返回、历史返回、POST 不确定状态。
- `tests/check_inbox_refresh_browser.py`：隔离真实 worker 的局部／全局增量更新及 F5 回归。

结果保存在 `data/ui-check/inbox-toolbar-browser-report.json` 和 `inbox-toolbar-confirmation.json`。界面截图使用隔离数据，不代表学校真实通知。
