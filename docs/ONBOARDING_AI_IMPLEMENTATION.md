# 公共目录与实例 AI：实施记录

更新日期：2026-09-24。对应 [完整实施方案](UNIVERSITY_ONBOARDING_AI_PLAN.md)。本文件区分已实现机制、实测结果与尚未完成的全名单验收。

## 已实现的行为

- 学校使用稳定登记身份与明确别名。并发订阅复用学校与任务；同域名、同网址不作为合并校区的依据。
- 已登记学校共用 `discover:学校ID` 接入任务。调查分轮保存进度，浏览器交接和等待资源不增加失败次数；有一个可用栏目不再阻止补齐其他学院。
- 学生关注信息优先调查和展示；其他有效栏目保留。机构身份、导航关系和内容主题分别处理。
- 新发现、手动提交、管理员修改、普通导入、YAML 初始化及自动修复均先生成候选，经过统一网页与归属检查后启用。已有健康配置及来源 ID 保留。
- 候选检查覆盖具体列表区域、相邻列表混入、文章样本、分页重复、独立复测和预期配置版本；一两条通知不自动判故障。
- 来源处理单、证据缓存、配置版本、审核记录和学校接入状态进入持久化存储。官方名录与重点入口仍有未检查项时，不宣称全校就绪。
- `university-source-onboarding` 和 `summarize-university-notice` 随项目部署，包含版本清单、提示词、参考、示例与输入输出契约。后端实际加载资源、校验证据并记录资源摘要。
- DeepSeek、百炼／通义、火山方舟、智谱使用各自官方接口适配；配置归整个部署实例，普通用户没有个人密钥或私有摘要分支。
- 新配置加密保存，改动后需管理员主动测试，再分配目录／摘要用途。失败不切换供应商或密钥。原有 DeepSeek 配置仅保持原摘要用途，目录用途需明确配置。
- 摘要只由点击或管理员指定的 1–50 个通知编号触发。相同通知及正文版本并发合并；已有有效摘要无需 API 即可阅读。更换模型或密钥不自动生成。
- 摘要按标题与完整正文校验版本，长文分段后汇总；失租和旧正文结果不能成为当前摘要。旧摘要保留为明确标注的历史版本。
- 普通数据包增量合并通知、正文、来源关系与摘要版本；未出现在本次同步／导入中的旧通知保留。导入栏目规则需重新检查，原有健康规则不被覆盖。
- 实例月度 token 预算可选，0 表示不设消费上限。并发保护独立生效。结果不明的请求保留账目，不自动重发；管理员可核对实际用量。
- 迁移新增 10 张表。完整备份及搬迁包含新表与栏目核实证据，主加密密钥另行保管。恢复后的未完成付费请求不会自动重放。

## 网页入口

1. **系统管理 → 平台设置 → AI 服务**：保存服务商、地域、模型、密钥，点击“测试连接（调用 API）”，通过后选择目录与摘要用途。
2. **通知详情 → 生成摘要**：查看当前摘要、执行状态与历史摘要。普通阅读不调用模型。
3. **系统管理 → 学校与部门 → 核实待确认的部门与栏目**：查看证据、确认归属、重新检查或拒绝建议；从安全快照点选通知行、标题、链接和日期，再提交统一检查。
4. **栏目订阅**：查看学校目录核对状态、已检查与剩余页面。部分可用不代表完整覆盖。
5. **存储管理**：统计栏目核实证据；清理保留仍被生效配置、待处理事项和机构名录引用的证据。

快照去除原网站脚本与外部资源，点选由服务器从保存证据生成规则。版本恢复也重新验证网页，不直接把旧规则覆盖为生效配置。独立机构名录与逐机构重点范围的登记、核实 API 已提供；完整名录维护向导仍可进一步完善。

## 本轮验证

最终完整隔离回归：610 项执行，589 项通过、21 项因未配置对应真实环境而跳过；包含独立审查后的身份、恢复与重复订阅修正。跳过项主要为实际 PostgreSQL 与实际浏览器／Linux 人工显示环境，不能记为通过。

- 100 个并发订阅复用一所学校和一个活动任务；100 个摘要请求复用一条记录与任务。
- 相同网址的不同校区、学校别名、导入保留身份、正文尾部变化、失租写入、未知收费结果不重放、长文覆盖、导入整体回滚均有回归用例。
- SQLite 全新安装、旧版本升级、历史摘要迁移、原生备份恢复、证据摘要校验及活动收费任务恢复保护已测试。另用当前数据库的一致副本完成升级演练：6 所学校、390 个来源、7,792 条通知、8 项订阅、2,990 项已读记录和 4 个账号数量保持不变，外键检查无异常。
- 桌面／手机浏览器已测试摘要、实例 AI 配置、来源核实与安全点选。没有 JavaScript 错误或横向溢出；恶意快照中的脚本、外部请求被阻止。
- 两个 Skill 通过标准资源校验，离线合同及证据校验使用模拟供应商响应；本轮没有调用真实收费模型。

主要自动测试位于 `tests/test_ai_runtime.py`、`tests/test_ai_migration.py`、`tests/test_shared_summaries.py`、`tests/test_source_governance.py`、`tests/test_source_picker.py`、`tests/test_school_registry.py`、`tests/test_onboarding_integration.py`。浏览器检查入口为 `tests/check_shared_ai_browser.py`，截图保存在 `.impeccable/review/`。

## 固定名单与后续验收

已保存 [201 个学校／校区的固定名单](acceptance/onboarding-scope-2026-09-24.json)，由 200 个内置条目和 1 个已登记补充校区组成。数量来自快照，不写死在实现中。[初始覆盖报告](acceptance/onboarding-initial-report-2026-09-24.json)记录 0／201 完成独立全校覆盖核验；这是完整性验收状态，不等于已有栏目不可用。未注册、未订阅、访问失败与未检查学校均计入报告分母。

提供以下管理命令，执行前应使用当前项目环境及目标数据库配置：

```text
flask --app app onboarding-scope <新的名单文件.json>
flask --app app onboarding-report <名单文件.json> <报告文件.json>
flask --app app onboarding-enqueue <名单文件.json>
```

前两项只读取业务数据，生成本地名单／报告；第三项明确安排公共目录任务，已配置目录 AI 时可能调用该服务。它不为无人订阅学校批量抓取全部通知正文。

以下验收尚未完成，不能据此宣称“名单中所有学校已达到交大效果”：

- 通用实现冻结后的 30 所未专门适配学校盲测、201 个学校／校区逐项独立覆盖核验及可发布的已核验全量目录包。
- 四家服务商分别使用可用凭据完成小额度真实调用、结构化输出与用量解析验收。管理页连接测试只证明该配置基本可用，不等于业务语义准确性验收。
- 本轮新增表与流程在实际 PostgreSQL、Windows／Linux 全新部署上的验收。此前抓取重构的 PostgreSQL 记录见 [原运行验收](RUNTIME_ACCEPTANCE.md)，不能替代本轮新增功能测试。
- 连续 14 天运行、100 并发用户与 1000 活跃来源混合负载、阅读接口 P95、浏览器资源与排队时延实测。
- 金额估算预算、完整可视化官方名录维护向导、翻页交互点选等尚未达到完整方案的全部交互要求；目前提供月度 token 额度、证据点选和管理 API。

本轮交付是可运行的接入治理与 AI 基础，并非上述全名单及服务器容量验收已经完成。
